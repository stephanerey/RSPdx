# PRD Authoring Playbook (for the assistant / agent)

> **PRD Policy:** **LOCKED (template)** — Do **not** edit this file in a project PRD. If you need project-specific changes, copy it to a new project note and reference it from `PRD.md`.

**Last updated:** 2026-03-12

## Operating principles
- Prefer explicit decisions over implicit assumptions.
- If information is missing, make a reasonable default, mark it as `TODO`, and list it under `01_product/open_questions.md`.
- Keep documents short and testable.
- Every deliverable MUST have verification steps.
- Keep traceability updated, not just tasks.
- Project truth lives in the core folders, not inside the packs.

## Workflow
1. Fill `PROJECT_PROFILE.md` and `01_product/*`.
2. Write explicit requirements in `04_requirements/*`.
3. Maintain the traceability matrix.
4. Select and scope the current phase.
5. Fill core architecture docs.
6. Write feature / API / interface specs.
7. Write testing and validation.
8. Read only the packs selected for the project, and reflect their guidance into the core docs.
