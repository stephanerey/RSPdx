# Project PRD — Human Guide

This document explains the **project PRD folder** once it has been instantiated from the master library.

## What this folder is for
This folder is the working PRD for a specific project.
It is the place where the project truth should live:
- scope
- requirements
- architecture
- tasks
- quality checks
- active packs
- domain truth when relevant

## Recommended starting point
If the project was just created and little is known yet, start with:
1. `PROJECT_INTAKE.md`
2. `PROJECT_PROFILE.md`
3. `PACKS_ACTIVE.md`
4. `01_product/product_brief.md`

If these three first files are still empty, fill them manually or generate them from the wizard before trying to complete the rest of the PRD.

## Main files to understand first
- `PROJECT_INTAKE.md` — compact initial framing
- `PROJECT_PROFILE.md` — project family, lifecycle, constraints, pack selection
- `PACKS_ACTIVE.md` — which specialized packs are actually active in this project
- `PRD.md` — project PRD top-level index
- `PRD_READY_CHECKLIST.md` — sanity check before implementation

## Practical rule
Do not try to fill the whole PRD in one shot.
Use the intake files to establish a clean first pass, then expand the PRD in a controlled way.
