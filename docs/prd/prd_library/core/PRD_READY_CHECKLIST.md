# PRD Ready Checklist

> **PRD Policy:** **PROJECT (editable)** — Use this checklist to assess whether a project PRD is sufficiently mature to start implementation or hand-off.

## Core completeness
- [ ] `PROJECT_INTAKE.md` is filled.
- [ ] `PROJECT_PROFILE.md` is filled.
- [ ] `PACKS_ACTIVE.md` is filled if any pack was imported.
- [ ] `01_product/product_brief.md` explains scope and intent.
- [ ] `04_requirements/requirements_catalog.md` contains explicit requirements.
- [ ] `10_architecture/overview.md` exists and is understandable.
- [ ] `02_tasks/tasks_now.md` contains actionable items.
- [ ] `90_quality/validation_matrix.md` contains verification rows.

## Pack discipline
- [ ] Only relevant packs were imported.
- [ ] Imported packs are recorded in `PACKS_ACTIVE.md`.
- [ ] Pack guidance has been reflected into core docs.
- [ ] No project-critical truth exists only inside pack notes.

## Traceability
- [ ] Important requirements are linked to implementation and validation.
- [ ] Open questions are explicitly tracked.
- [ ] Risks and assumptions are documented.


## Optional Codex readiness
- [ ] A repo-level `AGENTS.md` exists if Codex will be used regularly.
- [ ] `AGENTS.md` points to the relevant PRD and domain entry docs.
- [ ] `PLANS.md` is available if the team expects long or multi-step Codex work.
